# Windows一键启动与可靠重启

双击根目录start-dev.cmd，等价于使用项目Python执行绝对路径run.py --restart --reload --open。优先使用项目.venv，不存在时用PATH中的Python。默认端口统一由run.py维护为8016；命令行可用--port选择其他端口。

## 一键启动流程

1. 检查依赖及当前YAML工况校验，失败时先报错，不先关闭已有可用服务。
2. 取得本项目本端口的启动互斥锁，串行处理重复点击。
3. 核对旧服务/api/runtime的项目根目录、PID、监听端口进程与祖先链；也检查本项目绝对路径启动器及有创建时间的项目PID记录，覆盖旧后端已退出但启动器仍在的情况。
4. 停止确认属于本项目、本端口的Python进程树，包括重载器、服务及计算worker。通过进程句柄核对创建时间，PID重用时拒绝操作；端口身份不明、其他项目或无法归属的相对路径旧启动器不会被强杀，明确报错且不启动第二份。
5. 等待旧进程退出、端口释放，确认没有本项目同端口启动器残留，再启动新实例。
6. 新Uvicorn进程先暂停，加入专属Windows Job Object后才执行。重载器/worker自动属于同一个Job，启动器退出或被终止会回收这些子进程，包括已失去父进程的worker。网页浏览器由Job外的启动器打开，不属于服务器Job。
7. 验证新实例随机标识、项目路径、实际服务PID及软件版本；只在当前新实例就绪后打开网页。原服务能响应不会被误当作本次启动成功。

窗口保持前台运行，Ctrl+C关闭本次服务及子进程。启动PID/实例状态和互斥文件位于artifacts/runtime/，属于本机运行记录，不提交Git。

## 命令行

- 明确重启：python run.py --restart --reload --open
- 停止本项目指定端口：python run.py --stop --port 8016
- 其他端口：python run.py --restart --reload --port 8123
- 未指定--restart时，已有且能证明属于本项目的服务可被复用；一键cmd始终传--restart。

本次可靠重启入口使用Windows进程/Job API，不增加依赖；其他系统可直接使用Uvicorn CLI。未知的老相对路径run.py孤儿如果没有服务身份或有效记录，需先在其原窗口手动退出一次；新一键启动使用绝对路径和创建时间记录，避免继续形成这种歧义。

重启会中止尚未完成的计算，原任务配置和历史完整结果保留，可重新提交。重启服务不会清除浏览器草稿或重写历史结果；验证新计算逻辑应点击运行生成新任务。缓存策略仍为JS/CSS内容指纹及no-store。

实际验证见[启动器验收](../../artifacts/launcher-restart/README.md)。
