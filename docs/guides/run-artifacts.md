# 运行数据、版本管理与复现

任务型仿真（A、独立SPAD、B、历史C、列级C）由同一运行管理器持久化。参数预览请求不等于提交采集任务，不能把预览图当成已采集数据。

## 保存位置

```text
artifacts/runs/
├─ jobs.sqlite3
└─ <任务ID>/
   ├─ request.json
   └─ result.json
```

- `jobs.sqlite3`记录任务类型、时间、状态、进度及结果路径。
- `request.json`保存解析后的工况、算法和整份配置YAML快照。
- `result.json`在成功完成后保存，包含配置/版本/时间/seed/指纹、物理预算、实际记录及该类模型的输出。失败或中断的任务可能只有输入，没有完整结果。
- 新B的重复统计保存各轮直方图；首次采集保存逐事件记录。不要据此声称每一轮都有逐事件数组或逐gate误差棒。
- 宽带无色差路径可用`outer_product`保存光谱矩阵，因子与形状完整保留。用`numpy.outer(pixel_factor, spectral_factor)`可重建；这是无损表达，不是采样省略。

关闭浏览器不会删除结果；重启服务可找回历史任务。当前没有自动过期清理。运行目录可能持续增大，备份/清理要显式进行。

## Git与本机数据边界

进入Git的是源码、唯一配置、文档、必要参考谱、数值基线，以及选定的验收报告和截图。原始运行目录、本地下载PDF、一次性客户端/知识库同步检查点和大型诊断重放数据被忽略，保留在本机；Git推送不等于这些资料已备份。

论文目录只提交来源索引与模型使用说明，PDF从索引中的官方入口另行获取。Zotero/Wiki中的副本属于独立资料系统，不是运行依赖。

## 备份与恢复

备份完整运行集合时，建议先等待任务结束、停止服务，再复制整个`artifacts/runs/`，包含SQLite文件及任务子目录。不要只备份数据库，也不要在运行中仅复制SQLite主文件而忽略可能存在的事务文件。

数据库中的`result_path`目前是本机绝对路径。恢复到相同项目路径最直接；迁移到另一目录/机器不能只复制数据库就假定任务链接可用，需检查路径并做显式迁移。任务目录内的配置和JSON仍可独立读取。

## 复现与对照

1. 保留源代码提交或版本、配置YAML、输入、seed及原始结果。
2. 历史结果的查看和合法分箱重放只读取记录；改变物理输入需要提交新任务。
3. 使用相同模型版本/依赖与随机协议时可比较逐事件结果；版本发生变化时，先确认迁移和模型语义，再判断是否应逐记录一致。
4. 对照A/B/C时先对齐每通道能量、角域/IFOV、像素布局、参考面、分箱和累计范围，不能只比较图上的峰高。
5. 候选率乘bin时长是解析数值，不需要额外统计。混合记录受到竞争，不能把独立关光结果简单相减当作精确信号分量。

近期验收目录的README说明哪些数组进入Git、哪些只留本机，以及对应任务ID和哈希。下载、客户端日志与运行记录不会作为参数默认值源。
