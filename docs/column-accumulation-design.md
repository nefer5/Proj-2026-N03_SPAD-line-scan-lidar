# 列内多次曝光与直方图累积：讨论结论

2026-09-25。用户已确认以下工作模式；B的10次重复、解析噪声标量和完全恢复初态已接入；本文件中的C列间复位、复位耗时及芯片直方图资源仍为后续细化方向。

## 已确认的边界

- 一个 slot 对应点云的一列，线阵所有读出通道同时参与采集。
- 累计发数表示该列内参与同一份通道 ToF 直方图累积的发射/曝光次数。
- 每次曝光以各自 Tx 触发为计时零点，按相对飞行时间写入同一组直方图时间分箱。
- 曝光之间重新开放首事件/命中次数额度；SPAD 死时间与 TDC 忙状态在同一 slot 内按真实时间延续。用户随后明确：slot 结束后器件完全复位，下一列从复位后的状态开始。
- 芯片内按列累积直方图。当前列的累积缓冲在 slot 开始清零，slot 结束锁存并交给 DSP；沿用已确认的双缓冲流水，上一列处理可与下一列采集重叠。已锁存的上一列输出不得被下一列复位清除。
- 用户选择复位放在两个 slot 之间，额外计入帧时间；复位耗时尚未提供。slot 有效采集时长与列启动间隔分开，高层帧率预算须单独核算该开销，并明确帧末复位与回扫是否重叠。
- 本模式不需要额外预热曝光；完整复位是目标硬件的显式模型假设，不是对所有 SPAD 硬件的通用推断。
- Monte Carlo 统计重复次数是整套工况的独立重复，用于误差棒，不是列内累计发数。

## 现有实现与需要补齐的部分

B 已通过周期采集程序逐发模拟，并把多次曝光的相对时间记录累加为通道直方图；并非把单发结果简单乘以发数。但 B 尚无显式列 slot 时间预算。

C 已有列内逐发时刻/能量列表、逐发或整列接收门、连续 SPAD/TDC 状态及按列的相对时间直方图。当前直方图主要由保存的事件记录重建；尚未完整模拟芯片内直方图累积器的计数饱和、写入能力和列末锁存/读出约束。transport 中的直方图位宽目前用于负载尺寸估算，不代表已经执行计数器饱和。

后续应复用同一份曝光程序与 SPAD 核心，显式区分曝光级额度、列级累积状态、整次仿真的计算资源预算。规则曝光模式由发数和间隔生成时刻列表；自定义列表模式的发数应从列表派生，避免出现两份矛盾输入。

以 slot 为20 μs、单次接收门2048 ns为例：若各门不重叠、完整落在本列内，且没有门延迟/复位/读出等额外开销，可放9次完整曝光；10次连续门需要20.48 μs。最后一门与列末输出的约束需要明确，不能只检查最后一个 Tx 触发是否落在 slot 内。物理回波拖尾仍需跨 slot 按到达时间处理；电子学复位不能删除已在传播的光子。

## 资源优化与说明图预览

诊断已单独按完全恢复初态、0预热运行同一个10发工况：预计147144.2526个候选，实际147125个，最终98694条记录，直方图总计数与记录一致。单次采集约1.46秒，包含cProfile开销，不包括光学投影和完整重复统计。该诊断不代表10发满足20 μs slot，也没有实现多列之间的复位或硬件累积器资源。完整诊断配置、算法和指纹在 `artifacts/readout-discussion/reset-initial-diagnostic.json`。

优先优化方向：

1. 去除本复位模式下无意义的预热，此10发工况的候选期望减少约44.4%。不应简单全局修改后宣称C列边界复位已实现。
2. 快速探索与完整统计分开：先提供一次观测，需要时再做重复/纯噪声采集。已选统计口径和省略内容必须显式标明；不能伪造误差棒。当前40+24次统计是另外的成本来源。
3. 优化已经测得的热点：窗口归属查找约0.35秒/单次，逐事件读出逻辑约0.52秒/单次，函数累计时间存在嵌套不能相加作为总耗时。可用批量窗口归属或游标，避免无待处理事件时反复flush/排序；须验证事件记录和边界判定一致。
4. 真正实现候选分块生成/处理与即时直方图累积，区分总工作量和峰值驻留预算。当前候选仍先整体生成，已有采集分块不等于内存峰值已受控；边界光子及非有限支持脉冲尾需正确处理。
5. 对相同条件、种子、算法和版本的纯噪声参考使用可追溯缓存；公共解析时间轴和核复用，减少JSON重复数组。对更改的物理参数正确失效缓存。

说明图设计预览：`/static/prototypes/slot-readout/index.html`。包含参数到处理环节的点选说明、单slot Tx/门/相对计时/累积图、列间复位与DSP/MIPI流水示意、资源预算解释。10发配置标明超时0.48 μs；9发仅为时长可容纳示意，未修改实际工况。复位时间仍标为待定。
