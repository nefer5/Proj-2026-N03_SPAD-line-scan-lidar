# A版审视与后续优化建议

更新：V0.2基线已封存（标签v0.2.0）；两个P0条目现已实现，见 [检测与性能扫参](detection-performance.md)。下表“当前依据”保留审视时的问题证据，P1/P2其余项仍是计划。

审视日期：2026-09-15。范围：单角通道核心、谱积分、事件读出、参数配置/API、测距指标、前端请求逻辑、文档及回归测试。不是量产芯片符合性评估，也没有将B/C功能提前纳入A。当前107项测试通过；通过回归测试不等于实测物理验证。

## 总体判断

目前已具备工程探索闭环：可复现参数、单通道光子预算、光谱联合积分、7种事件读出族和解析对照、原始直方图、重复测距和调试输出。最重要的缺口是“有无目标检测与指标可信度”，而不是继续增加光学建模复杂度。

| 优先级 | 建议 | 当前依据 | 建议验收 |
| --- | --- | --- | --- |
| P0 | 增加检测门限、无目标实验、Pd/PFA及置信区间 | `_estimate_range`只找峰和质心；当前本地配置将pulse_energy_nj设为0后，40/40次仍有距离输出，容差成功率为0。该结果说明没有拒绝纯噪声的检测机制，不是已测得某个PFA | 无目标校准集与评估集分开；报告搜索门、门限、虚警口径、Pd/PFA、样本数及置信区间；允许明确“未检出” |
| P0 | 扫距、扫照度、扫累计发数采用所选事件引擎 | `_range_sweep`目前只计算未计pile-up/门截断的理想预算，不能当所选读出模式的最大测距 | 每个点返回同一模式下的检测/偏差/精度/失败率及MC区间；保留理想曲线作标明的对照 |
| P1 | 噪声来源标签和实际记录的归因 | 预算分四类，`event_histogram`生成时合并噪声，`route_events`没有来源标签 | 记录候选来源、SPAD/TDC拒绝原因；符合触发支持多来源归因，不能强行将混合触发归属单光源；总数守恒 |
| P1 | 实测时间IRF与TDC非理想性 | 目前SPAD/电子抖动为独立高斯，TDC只有理想bin；估计核根据输入波形宽度设定，未检验模板失配 | 导入归一化IRF，检查非负/积分；比较高斯与实测尾部、脉冲相对bin相位、DNL/INL和时间偏置；保留理想模式 |
| P1 | 参数来源/工作条件的配置档案 | 目前PDE、DCR、抖动来自不同参考，数据口径已注明但没有统一器件工况档案 | 一个档案记录来源、温度、过压、参考面及模型差异；不要暗中把PDE/FF重复折减，也不自动猜测芯片拓扑 |
| P1 | 单通道相关噪声：afterpulse、内部延迟反射、器件串扰 | 目前只含独立泊松背景；独立串扰矩阵不影响直方图 | 参数置零退化回当前结果；事件因果关系、延迟核、恢复抑制与级联稳定性可核对；与B版PSF串扰区分 |
| P2 | 仿真进度、取消与批量任务 | `/api/simulate`同步返回；前端fetch没有超时/取消，只有资源上限和运行按钮状态 | 后台任务有进度、取消、失败详情；取消后释放计算资源，不继续占用后端；旧结果标记过期 |
| P2 | 减少配置数据副本并固定复现环境 | 默认PDE CSV与YAML采样点需同步；配置指纹没有包含Git代码或依赖版本；源码依赖有下界但无锁文件 | 本地文件引用有受限路径和校验和，上传数据仍能自包含导出；报告记录代码版本/脏状态、依赖和数据指纹；全新环境复现实验 |

## 建议下一轮只做两件事

先完成P0的“检测判定和置信区间”，再将它接到相同事件引擎的扫参中。这样才能回答“某距离/太阳照度/累计发数下，有多大概率测到且不虚警”。真实IRF和相关噪声可作为之后的真实性增强。

保留A边界：这里的扫参是固定单角通道工况比较，不计算转镜驻留；空间能量/PSF映射留给B，扫描调度留给C。
