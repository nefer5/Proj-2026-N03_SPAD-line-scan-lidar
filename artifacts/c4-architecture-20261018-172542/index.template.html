默认值、输入与结果分开管理

当前没有独立的“用户默认参数库”。项目初始默认值在 YAML；用户页面草稿主要在浏览器存储，完整工况也可从历史任务或导入文件恢复。网页编辑不会写回 defaults.yaml。
① 读取初始默认defaults.yaml 的公共值与平台差异，经类型和约束校验。
② 用户编辑 / 恢复表单、浏览器草稿和导入文件形成当前输入，可覆盖初始默认。
③ 提交采集后端规范化后写 request.json，保存实际工况、算法和完整 YAML 快照。
④ 保存结果worker 写 result.json，状态存 SQLite；原始导出文件由用户选择位置。

各平台初始值的来源

浏览器如何记住输入

localStorage 跨浏览器会话保留，sessionStorage 用于当前会话/页面转移；二者均按浏览器 Profile 与页面来源隔离。清除浏览器数据不等于删除服务端任务。

预算例外：calculate 是同步计算，不自动生成采集作业。预算草稿、比较基准保存在浏览器；用户点击导出后才得到本机 JSON 文件。
设计建议 · 尚未迁移

默认值也应与领域模块对齐

建议在唯一的 defaults.yaml 内组织 domains.tx / scene / rx / spad / readout / timing / spectral_inputs，各实验只声明适用领域与必要差异。类型定义在 Python，数值源在 YAML，用户命名方案通过显式导入/导出成为覆盖值。

目前仍是 simulation 基础值 → B领域映射 → C/预算继承与覆盖。暂未拆成 tx.yaml/rx.yaml，也不建立第二份默认数值。网页草稿、已提交任务和未来用户方案不冒充模块默认。
