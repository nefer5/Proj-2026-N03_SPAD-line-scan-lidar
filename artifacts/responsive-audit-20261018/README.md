# 网页适配只读审查 · 2026-10-18

结论：已有响应式基础，常见桌面窗口下没有发现整页横向撑破；主要不足是缩放后有效空间变小的情况下，可读性、操作空间及结果可达性下降。应优先改工作区重排、图形标注和高度策略，再考虑超宽屏利用率。本轮不修改应用代码、配置或项目设计决策。

## 问题与建议

### 优先1：预算细节图缩小后标注难读

1280×600下，参数栏仍为360px，结果区约813px，三维细节图区域约767px；两个细节卡继续左右并排，各卡约375px。图形以固定viewBox整体缩放，部分文字折算约6–9 CSS px；960×440时部分降至约4–6px。该值为SVG字体与变换比例的近似值，受具体标签样式影响，不是对所有文字的统一测量。

证据：[1280细节图](budget-detail-1280.png)、[960细节图](budget-detail-960.png)。

建议：按细节卡自身可用宽度提前改单列；保留坐标、单位和说明的可读大小。需要时改变图形排版、减少非必要刻度或提供局部放大；不只把整张SVG连同文字缩小。科学坐标比例和数据含义继续保持。

### 优先1：A单栏后结果离开工作区

从1101px到1100px，A参数区由420px侧栏变为整行，取消高度约束。当前初始展开状态参数区高约4173px，结果在其后，用户需要滚动很长距离才能核对；1100px附近页头标题也出现不理想的断行。A调试页同样存在参数先占据长页面的问题。

证据：[1101px](a-1101.png)、[1100px](a-1100.png)、[960结果区](a-results-960.png)。

建议：窄窗采用“参数/结果”工作区切换、可收起参数抽屉或有明确高度边界的配置面板；保留提交、状态与返回参数入口。先明确专业工具最小支持视口，不必强求全部信息同屏，也不能通过删除参数改善表面长度。页头应有独立换行/菜单策略。

### 优先1：矮窗口里侧栏操作占比过大

B在960×440下参数面板高约408px，头尾动作及说明占用后，中间表单仅约133px；1920×940时同一区约624px，1280×600时约293px。C在960×440下中间参数区约181px。虽能滚动，但反复核对多组参数很费力。

证据：[B矮窗口侧栏](b-short-960.png)；原始几何信息见JSON。

建议：增加高度维度的布局策略；矮窗口精简常驻说明与重复动作，将次要项收起，保证中间参数工作区；侧栏可临时展开为更大的编辑区。统一各页面的滚动职责，不统一成一种固定栏宽。

### 优先1：预算三维画布未跟随DPR变化

源码仅在初始化调用renderer.setPixelRatio，ResizeObserver回调只更新setSize与相机。浏览器模拟实测：初始DPR1.5、画布CSS宽约765px，绘图缓冲宽1147px；改为DPR2后缓冲仍为1147px。原有上限2的资源取舍可以保留，但需要在DPR变化时重新评估并设置。

证据：[dpr-change.json](dpr-change.json)；不是实际跨屏拖动实测。A的已显示Canvas在尺寸变化后能按DPR重绘，是应保留的已有能力；尚不能推定所有页面、隐藏图或跨屏场景均通过。

建议：统一容器尺寸与像素密度变化后的刷新入口，适当观察DPR变化；展开隐藏图、切换工作区后也校正绘图。清晰度与布局重排分别验收。

### 优先2：超宽窗口未充分用于分析

3440px宽时，预算内容仍为1800px，B为1720px，C为1690px，A为1600px；分别仅占窗口约52%、50%、49%、47%。限制正文宽度有价值，这不属于页面损坏；但专业工具仍有较多可利用横向空间。

证据：[预算超宽窗口](budget-3440.png)。截图显示缩小时请留意原图尺寸，不能据聊天预览判断真实字号。

建议：默认阅读宽度保留，可提供宽工作台模式，将空间用于主图、辅助检查或方案对比。参数输入不无限拉长，不能为填满屏幕把所有文字和图形放大。

### 优先2：规则分散，维护容易相互覆盖

A、预算、B/C改单栏阈值分别为1100、760、850px；这些差异本身不必消除，但目前缺少共同的支持范围与行为约定。预算main、scene-layout、scene-viewport与scene-inspector在多处重复覆盖，已出现“前面写了三列，末尾实际两列”等情况。

建议：先定义页面级/组件级的职责、最小可读空间与滚动规则，再合并受影响区域的重复样式；不开展无关CSS重构。通过组件容器空间确定细节卡布局，避免页面宽度充足却因参数栏挤压导致组件仍过窄。

## 推荐后续实施顺序（未实施、未人工验收）

1. 先处理1280×600和矮窗口：预算细节图重排、A参数/结果可达性、B/C侧栏操作区。
2. 再处理图形生命周期：尺寸、DPR、折叠展开、标签页切换后的重绘；同时保留科学坐标与原始数据。

4. 验收覆盖代表性视口及断点两侧，加入长标签、展开参数、正常结果、运行/错误状态。真实Windows缩放与浏览器缩放分别测，最后补跨显示器拖动。C先需有可用的有效计划场景，本次不以错误页布局代替。
